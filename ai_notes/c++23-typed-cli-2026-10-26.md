## Typed CLI helpers

`libs/libhrutil/ScuffCLI.h` is an internal header (not installed, no CLI11 in
the public interface).  It provides three entry points:

| API | Purpose |
| --- | --- |
| `scuff::cli::CollectArgs(argc, argv)` | Reads the legacy stdin option-file format, combines it with argv, and returns the reversed token vector that `CLI::App::parse` expects. |
| `scuff::cli::Parse(App, argc, argv)` | Sets the application name, parses, and returns `std::nullopt` on success or a process exit status on failure. |
| `scuff::cli::AddComplexOption(App, name, value, description)` | Declares a scalar complex option parsed with the legacy `S2CD` syntax. |

### Stdin and argv ordering

The option-file reader preserves the Stage A contract:

- lines are `Name value1 value2 ...`, with optional `--` before the name;
- blank lines and lines whose first token starts with `#` are ignored;
- more than 50 tokens on a line aborts, matching `ProcessOptions`;
- stdin occurrences are applied before argv occurrences;
- the first value is attached as `--Name=value` so that a value beginning
  with `-` cannot be mistaken for another option;
- the complete normalized stream is reversed because CLI11's vector parser
  consumes tokens from the back.

For a scalar option configured with `->take_last()`, argv therefore overrides
a value supplied in an option file, just as the legacy `MaxInstances=1`
handling did.

### Complex values

CLI11's built-in `std::complex` converter splits at the last `+` or `-` and
therefore rejects valid scientific notation such as:

```text
1e-3-4e-2i
```

It also recognizes only lowercase `i`/`j`.  `AddComplexOption` binds the
option to a `std::string` and converts it through `S2CD`, which preserves:

- uppercase and lowercase `I`/`J`;
- exponent notation with negative exponents;
- the legacy single-token forms (`3+4i`, `3i`, `-2.5`);
- rejection of trailing garbage (`1+2x`).

The helper configures `->expected(1)` so a complex option consumes exactly
one token, as `PA_CDOUBLE` with one argument did, and `->take_last()` so
repeated scalar occurrences are last-wins.

### Exit behavior

`Parse` returns:

- `std::nullopt` when parsing succeeded;
- `0` for `--help` / `-h`;
- `1` for any parse error.

CLI11's distinct internal error codes are deliberately collapsed to `1` to
match the legacy parser's exit status.  The message format and generated help
are CLI11's rather than the old `OSUsage` banner.

## `scuff-tmatrix` migration

The application's `OptStruct` array is gone.  The declarations are now:

| Option | Type | Behavior |
| --- | --- | --- |
| `--geometry` | `std::string` | Required; last occurrence wins. |
| `--LMax` | `int` | Default 3; last occurrence wins. |
| `--Omega` | `cdouble` | `S2CD` syntax; default 0; last occurrence wins. |
| `--OmegaFile` | `std::string` | Takes precedence over `--Omega`, as before. |
| `--Cache` | `std::string` | Optional cache file. |
| `--FileBase` | `std::string` | Optional output base; defaults to the geometry basename. |
| `--WriteHDF5Files` | `bool` | Flag. |

All names remain case-insensitive through `option_defaults()->ignore_case()`.
The missing-frequency check is still performed after parsing, because CLI11
does not have a declarative "one of these two options" rule: supplying neither
`--Omega` nor `--OmegaFile` produces a `CLI::ValidationError` and exit status
1.  The legacy rule that `--Omega 0` counts as unspecified is retained.

Path and frequency handling also moved from fixed buffers to owned storage:

- `GeoFileName`, `OmegaFile`, `Cache`, and `FileBase` are `std::string`;
- `OmegaVector` is a `std::unique_ptr<HVector>`;
- the HDF5 output name is composed with `std::string` instead of a 100-byte
  `snprintf` buffer, so long file bases no longer truncate.

## Tests

### Typed CLI unit suite

`tests/unit/ScuffCLITest.cc` adds seven forked scenarios.  Each scenario runs
with a private stdin pipe (or `/dev/null`) and reports its own failures; the
parent verifies the child status.  The 31 child-side checks cover:

- case-insensitive option names, negative integers and reals, a bool flag,
  a single-dash string value, and the automatic application name;
- complex scientific notation with an uppercase imaginary unit
  (`1e-3-4e-2I`);
- stdin-before-argv ordering and last-wins overrides;
- an option file supplying every value with no argv options;
- numeric conversion errors, a missing required option, an unknown option,
  and an invalid complex value;
- `--help` returning 0;
- an unknown option in stdin returning 1.

`tests/unit/CMakeLists.txt` registers the target as `TypedCli` (120 s
timeout).

### Application smoke test

`tests/CMakeLists.txt` registers `TMatrixCli`: a one-frequency, `LMax=1`
SphericalShell run.  The geometry and both mesh files are copied into the
build tree at configure time, so the test does not depend on the example
directory being writable or on the caller's working directory.  The test
exercises option parsing, geometry loading, the BEM solve, and T-matrix
output.

### CI

The sanitizer job now builds `scuff-typed-cli-tests` and `scuff-tmatrix`,
runs `TypedCli` with leak detection enabled, and runs `TMatrixCli` with leak
detection disabled (the pre-existing application-level ownership backlog is
unchanged).

## Compatibility notes

Retained behavior:

- case-insensitive option names;
- stdin option files, applied before argv;
- negative and single-dash values;
- last occurrence wins for scalar options;
- complex syntax through `S2CD`;
- `--OmegaFile` precedence over `--Omega`;
- strict numeric parsing (no trailing garbage).

Deliberate differences for typed applications:

- `--help`/`-h` and CLI11-formatted diagnostics replace the legacy usage
  banner;
- repeated scalar options no longer print the legacy warning;
- CLI11's bare `--` end-of-options marker is accepted (with no positionals it
  is harmless); the Stage A adapter still treats bare `--` as an unknown
  option;
- error exit codes are normalized to 1 even though CLI11 uses distinct
  internal codes.
