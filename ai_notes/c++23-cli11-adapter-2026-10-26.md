# C++23 CLI11 Stage A adapter — 2026-10-26

Status: **implemented and validated**.  This note records the first stage of
the CLI11 migration described in
`ai_notes/c++23-migration-plan-2026-10-26.md`: the hand-written option parser
in `libhrutil` has been replaced by a CLI11-backed compatibility adapter.
Individual applications still use their `OptStruct` arrays; the typed
per-application migration is Stage B and remains open.

Implementation commit: `efafc09c [libhrutil] Replace option parsing with a
CLI11 adapter`.

## What changed

`libs/libhrutil/ProcessOptions.cc` no longer contains a second option parser.
It now:

1. resets every `OptStruct::NumInstances` counter;
2. reads legacy `Name arg...` option files from stdin when stdin is not a
   terminal, accepting both bare and `--`-prefixed names;
3. scans argv using the legacy boundary rule — a token beginning with `--`
   starts a new option and every other token is a value;
4. normalizes each occurrence to a `--Name=firstValue` token followed by the
   remaining values;
5. lets CLI11 recognize the options, re-check arity, and generate `--help`;
6. stores the collected strings into the legacy `void *` storage in
   declaration order, applying `MaxInstances` and `ZeroArgs` bookkeeping.

CLI11 is used for option recognition, arity validation, case-insensitive
matching, and help generation.  The legacy `OptStruct` API, its storage
layout, and the application call sites are unchanged.

## Compatibility behavior

| Behavior | Adapter behavior |
| --- | --- |
| Option spelling | Case-insensitive everywhere (`option_defaults()->ignore_case()` plus per-option `ignore_case()`). |
| Stdin syntax | Bare `Name arg...` and `--Name arg...`; comments and blank lines ignored. |
| Stdin ordering | Stdin occurrences are applied before argv occurrences. |
| Stdin errors | Always abort with legacy usage, even when `AbortOnUnknown=false`. |
| Unknown argv options | Abort by default; skipped when `AbortOnUnknown=false`. |
| Repeated options | Preserved `MaxInstances` semantics: last value wins with a warning when the maximum is one; exceeding a larger maximum aborts. |
| Multi-value options | `NumArgs` values per occurrence, repeatable up to `MaxInstances`. |
| Boolean flags | Reject values; repeated flags warn as before. |
| Negative values | Accepted; only a `--` prefix starts a new option. |
| Single-dash values | Accepted, including filenames such as `-mesh.msh`. |
| Bare `--` | Still treated as an unknown option, matching legacy behavior. |
| `ZeroArgs` | Consumed argv slots are set to null exactly as before. |
| Numeric conversion | Strict full-string `strtol(..., 0)` / `strtod`; trailing garbage is rejected. |
| Integer bases | Base-0 syntax is retained (`0x10` is 16). |
| Complex values | Stored through `S2CD`, preserving the existing `i`/`j` syntax. |
| Invalid numeric values | Abort by default; skipped when `AbortOnUnknown=false`. |
| Help | New `-h` / `--help` / `--HELP` support; exits successfully. |

Deliberate changes from the legacy parser:

- numeric arguments with trailing garbage (for example `1foo`) are rejected
  rather than silently truncated by `sscanf`;
- `--help` was added (legacy printed usage only on errors);
- `ProcessOptions(const char *)` continues to work through the same adapter
  by synthesizing a program-name slot.

Error paths still use the legacy `OSUsage` banner and exit status 1 so that
existing scripts and examples see the same failure behavior.

## CLI11 integration details

Several CLI11 behaviors required explicit handling:

- **Token order.**  `App::parse(std::vector<std::string> &)` consumes tokens
  from the back, just as the `argc`/`argv` overload does after reversing
  argv.  The normalized token vector is therefore reversed before parsing.
  Without this, repeated and multi-value options are associated with the
  wrong occurrence.
- **Repeated occurrences.**  A `std::vector` target makes CLI11 infer an
  unbounded option.  The adapter calls `type_size(NumArgs)` and then
  `expected(1, 1000000)`: this keeps repeated occurrences working and lets
  generated help show the declared arity.
- **Leading dash values.**  The first value of each occurrence is attached
  with `=` (`--Direction=-1`), so a value that looks like an option cannot be
  mistaken for the start of a new occurrence.  An empty first value cannot
  use this form (CLI11 treats `--Opt=` as missing), so it is emitted as a
  separate empty token.
- **Help placeholder.**  Boolean options are registered with `add_flag` so
  they do not advertise phantom arguments.  Non-boolean options get a
  `TEXT` / `INT` / `FLOAT` / `COMPLEX` placeholder, with ` x N` for
  multi-value options.
- **Program name.**  `App.name(ProgName)` keeps the invocation path in
  generated help.
- **Internal consistency.**  After parsing, the adapter verifies that the
  number of collected strings equals `occurrences * NumArgs` (or the number
  of flag occurrences) and reports an internal error instead of silently
  misaligning storage.

## Tests

`tests/unit/CliOptionsTest.cc` adds 28 cases and 72 checks.  Error and help
paths call `OSUsage`, which exits, so each case runs in a forked child with
captured stdout/stderr and a private stdin pipe.  Child-side check counts are
propagated to the parent through a marker line.

Coverage includes:

- all legacy types (`PA_STRING`, `PA_INT`, `PA_DOUBLE`, `PA_CDOUBLE`,
  `PA_BOOL`) and multi-value options;
- case-insensitive option names;
- negative and complex values;
- repeated options, last-wins warnings, and `MaxInstances` overflow;
- stdin option files, stdin/argv ordering, comments, and malformed lines;
- strict numeric parsing and base-0 integers;
- missing and extra arguments, boolean values, unknown options, and bare `--`;
- `--help`, `-h`, and `--HELP`;
- `ZeroArgs` and `AbortOnUnknown=false`;
- empty and single-dash string values;
- the `ProcessOptions(const char *)` overload.

`tests/unit/CMakeLists.txt` registers `scuff-cli-tests` and the CTest test
`CliOptions` (120 s timeout).  The suite is dependency-free, like the existing
`scuff-unit-tests` harness.

  except `scuff-plotEpsMu`, which does not call `ProcessOptions`.

The full build still reports the 16 pre-existing `-Wformat-truncation`
warnings recorded in the Phase 1 note; the adapter and its tests add none.
