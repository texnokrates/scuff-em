## libhrutil hardening (`9e3f8dce`)

### Path and string helpers

- `RemoveDirectories`, `RemoveExtension`, `GetFileExtension`, and
  `GetFileBase` now copy into thread-local buffers with explicit bounds and
  guaranteed NUL termination.  They accept `const char *`.
- The helpers only treat dots in the final path component as extensions
  (`/a.b/c` is unchanged).
- `GetFileExtension` no longer uses the unexplained literal `999` as a bound.
- `fopenPath` now builds search-path candidates with `std::string` and bounds
  the returned directory buffer.  It also handles empty path components.
- `CreateUniqueFile`, `GetTimeString`, `GetHostName`, and `SetCodeMarker`
  use bounded copies; `GetTimeString` uses `localtime_r`/`localtime_s` and
  thread-local storage.

### Complex-number parsing and formatting

- `S2CD` was rewritten around `strtod` and now requires the complete string
  to be consumed.  It accepts `i`/`j`/`I`/`J`, whitespace around signs, and
  rejects trailing garbage such as `1foo` or `3+4x`.
- `CD2S` formats into `STRLEN`-sized buffers instead of `MAXSTR`, fixing the
  old size mismatch.  The no-conversion-specifier path uses `snprintf`.
- `z2s(cdouble, char *, size_t)` was added; the old two-argument overload
  remains for source compatibility.
- Format and buffer state used by these helpers is thread-local.

### Token and option parsing

- `Tokenize(char *, char **, int, ...)` now stores at most `MaxTokens`
  entries, reports truncation through an optional `bool *`, and handles
  `MaxTokens <= 0`.
- The stdin option-file reader rejects over-long token lines instead of
  silently dropping them.  Error messages are formatted into a separate
  buffer rather than overwriting the input line.
- The argv reader checks array bounds before dereferencing.
- `ProcessOptions(const char *, OptStruct *)` now preserves the first option
  in the argument string (the argc/argv overload expects a program name).

## Defect fixes (`457a6a98`)

- `scuff-integrate`: `RowStarts` was written past the end of a
  one-element vector.  It is now built with `push_back`, and
  `NumParmValues` is derived from the resulting size.
- `SommerfeldIntegrator`: the verbose diagnostic dereferenced `Integral2`
  after `delete[]`.  Logging now happens before the deallocation.
- `StaticSolver::PlotChargeDensity`: `snprintf` wrote a formatted name into
  the same buffer used as its `%s` input.  Formatting now uses a separate
  buffer.
- `cmatheval/node.c`: added missing returns in `node_copy`,
  `node_simplify`, and `node_derivative`, and explicit `break`s after the
  unary-operation switches in `node_evaluate` and `node_derivative`.
- `Interp1D`/`2D`/`3D`/`4D`: `LogLevel` is initialized to
  `LMDI_LOGLEVEL_TERSE`, copied by the `Interp1D` copy constructor, and the
  eight `"could not open file %s"` diagnostics now receive `FileName`.
- `scuff-ldos`: `--Lambda` used the `OmegaVals` array instead of a separate
  `LambdaVals` array, corrupting mixed `--Omega`/`--Lambda` input.
- `scuff-scatter`: the `--IFFile` conflict check tested the always-null
  `IFList` pointer instead of `IFFile`.
- `scuff-transmission`: a `FILE *` was passed to a `%s` diagnostic; the
  output filename is now reported instead.

## Format checking (`6d1fcecf`)

`SCUFF_PRINTF_FORMAT` (a portable `__attribute__((format(printf, ...)))`
wrapper) was added to the libhrutil varargs API:

- `ErrExit`, `Warn`, `Log`, `LogC`, `LogThread`, `MutexLog`
- `SetLogFileName`
- `vstrdup`, `vstrappend`, `vstrncat`
- `vfopen`, `vmkdir`, `vsystem`, `vsetenv`, `vsnprintfEC`
- `AppendEnv`, `ASUsage`, and both `OSUsage` overloads

The resulting diagnostics exposed real defects, all of which were fixed:

- missing `__FILE__`/`__LINE__` arguments to `"%s:%i"` errors;
- missing or extra filename arguments;
- `size_t` values formatted with `%i` (now `%zu`);
- `#i`/`#03i` typos that were printed literally instead of `%i`/`%03i`;
- a swapped `NumTokens`/`NumParameters` argument pair;
- an extra argument passed to a format without a conversion;
- a `%lu` format paired with a non-matching argument.
